Quick CVE Check - Usage Guide
Overview
The quick_check.py script provides on-demand CVE checking against your Tenable environment. It's designed with two modes:

Clean Mode (default): Executive-ready output for presenting to leadership
Debug Mode: Detailed technical output for troubleshooting

Quick Start
Basic Usage (Clean Output)
bash
python quick_check.py CVE-2024-1234

Output Example:
======================================================================
              Hyperion CTI - Quick CVE Check
                     2024-12-11 14:30:45
======================================================================

✓ Connected to Tenable

Checking 1 CVE(s)...
  [1/1] CVE-2025-62215... 🚨 VULNERABLE

Detailed Results
----------------

CVE: CVE-2025-62215
  Status:           🚨 VULNERABLE
  Affected Assets:  1
  Severity:         CRITICAL
  Details:          1 asset(s) affected
  ⚠️  ACTION REQUIRED

Debug Mode
bash
python quick_check.py CVE-2024-1234 --debug

When to use: Troubleshooting API issues, verifying filter syntax, or investigating unexpected results.

Multiple CVEs
bash
python quick_check.py CVE-2024-1234 CVE-2024-5678 CVE-2024-9012

Use Cases

1. Ad-Hoc Request
Scenario: "Can you quickly check if we're vulnerable to CVE-2024-XXXX?"

bash
python quick_check.py CVE-2024-XXXX

Screenshot/copy the output and send directly to leadership. The clean format is ready for presentation.

2. Morning Security Brief

Scenario: Check multiple high-profile CVEs announced overnight

bash
python quick_check.py CVE-2024-1234 CVE-2024-5678 CVE-2024-9012

Use the Executive Summary section for your security briefing.

3. Incident Response

Scenario: New CVE announced with active exploitation

bash
python quick_check.py CVE-2024-XXXX --debug > incident_report.txt

Debug mode provides full technical details for incident documentation.

4. Vendor Security Advisory
Scenario: Vendor announces multiple CVEs affecting their product

bash
python quick_check.py CVE-2024-0001 CVE-2024-0002 CVE-2024-0003 CVE-2024-0004

Quickly triage which CVEs actually affect your environment.

Command-Line Options

Option | Description
CVE-XXXX-XXXXX: One or more CVE IDs to check
--debug or -d: Enable verbose debugging output

Output Interpretation

Status Indicators
Symbol | Meaning | Action Required
🚨 VULNERABLE | CVE affects your assets | IMMEDIATE - Review and patch
✓ Clear | CVE not found in environment | None - Monitor
⚠ Error | API error occurred | Check debug mode

Severity Colors (Terminal)

RED - Critical severity
YELLOW - High severity
BLUE - Medium severity
GREEN - Low severity

Exit Codes

0 - Success, no vulnerabilities found
1 - Vulnerabilities found (useful for automation/scripts)

Tips for Presentations

Use Clean Mode - Default output is designed for executive consumption
Screenshot Ready - Color-coded output is clear in screenshots
Executive Summary - When checking multiple CVEs, lead with the summary
Action Items Clear - "ACTION REQUIRED" makes priorities obvious
Asset Counts - Provides scope for prioritization

Integration with Daily Reports
The tenable_checker.py script runs the full daily check with all CVEs from Hyperion. Use quick_check.py for:

Ad-hoc requests
Urgent CVE announcements
Verification after patching
Leadership inquiries

Troubleshooting
Connection Issues
bash
python quick_check.py CVE-2024-1234 --debug
Check the debug output for API connection errors, verify .env configuration.
No Results Found (But Should Be)

Verify CVE format: CVE-YYYY-NNNNN
Check if CVE is in Tenable scan results (may need to scan first)
Use debug mode to see API response

Rate Limiting
If checking many CVEs, add small delays between runs or use the main tenable_checker.py for bulk operations.
Best Practices

Regular Updates - Keep Hyperion data fresh to ensure accurate checks
Document Checks - Save output when responding to leadership requests
Combine with Context - Use alongside CVSS scores and exploit maturity data
Follow Up - After patching, re-run to verify remediation
